# Outreach Message Templates

These templates are intentionally short, technical, and non-salesy. They are for manual use only.

## 1. First LinkedIn connection

> Hi [Name], I work with medical infrastructure and imaging projects at ZES MEDCORP. I would be glad to connect and share a few technical resources that may be useful for your work.

## 2. First outreach message

> Hi [Name], I noticed your focus on [project type]. We recently put together a few practical resources on planning, room readiness, and infrastructure decisions. If helpful, I can share the most relevant one.

## 3. Follow-up message

> Hi [Name], just following up in case this is still relevant. If the project is moving forward, I can point you to a calculator or planning guide that helps structure the next step.

## 4. Proposal Builder introduction

> If the project is already taking shape, Proposal Builder can help organize the main assumptions, dependencies, and next steps before a final technical discussion.

## 5. Calculator recommendation

> If you want a quick directional estimate first, I can send the calculator that matches the project type. It is meant for planning, not for a final offer.

## 6. Technical validation follow-up

> Based on the information you shared, the most useful next step may be a technical validation of the room, equipment, and constraints. That usually makes the rest of the discussion much clearer.

## 7. Clinic modernization discussion

> For modernization projects, the main risk is usually downtime and hidden constraints in the existing space. If you want, I can share a short checklist that helps structure that discussion.

## 8. RF shielding discussion

> If the project includes RMN, it is worth separating RF shielding from radioprotection early. That distinction changes the room design and the implementation path.

## 9. Radioprotection / CT discussion

> If the project includes CT or RX, the key topics are radioprotection, layout, and the timing of CNCAN-related work. Those are best clarified before the room is finalized.

## 10. Service / uptime discussion

> If the main issue is uptime or equipment reliability, we should probably start with service triage instead of a generic project discussion. That saves time on both sides.

## Usage notes

- Keep the message short.
- Mention only one resource or next step.
- Replace placeholders with real context.
- Never promise a final technical approval in a LinkedIn message.
